# NanoSlice technical prototype
Ender 3 V2 stock 0.4 mm, browser-local Cura WASM 1.5.2 (archived upstream).
Build: npm ci && node build.mjs
Static output: dist. No model is uploaded. Offline cache requires HTTPS and retained browser storage. No physical-phone or printer verification yet.
Cura WASM upstream: https://github.com/Cloud-CNC/cura-wasm
Engine source: https://github.com/Cloud-CNC/cura-engine
Engine modifications: https://github.com/Cloud-CNC/cura-wasm/blob/main/docker/CuraEngine.patch
Cura definitions: https://github.com/Cloud-CNC/cura-wasm-definitions
CuraEngine: AGPL-3.0-or-later; definitions: LGPL-3.0-or-later; wrapper portions MIT. Upstream code and license notices are included under source/upstream. Application source is AGPL-3.0-or-later.

Version 0.2: corrected double bed-centre offset (mesh offsets now zero); old G-code must be regenerated. Added local layer inspection, build-volume checks that block out-of-bounds downloads, estimate correction from engine metadata, versioned offline shell with verification, and mobile installation instructions. Layer preview excludes non-extrusion moves. Browser QA: 20mm cube, 100 layers, volume check passes, layer 51 at Z10.2. Physical phone/printer and airplane-mode tests remain pending. Tests: npm test.

Version 0.3: quarter-turn orientation X/Y/Z on actual mesh geometry, grounding and centering after rotations, restore original orientation and scale, immediate build-volume fit checks, browser-local validated print preferences with PLA reset, rectangular demo. Geometry tests include STL export/reload to ensure rotation and scale reach slicing. Browser QA: rotated 20x30x40 prism becomes 20x40x30 and slices to 150 layers at .2mm with zero out-of-volume moves; infill preference survives reload. Physical phone and printer tests remain pending.

Version 0.4: explicit local print suggestion with review/apply. Geometry heuristic compares six orthogonal orientations; favors bed contact, lower height and fewer downward facets. Goals balanced/strength/finish use editable presets for PLA. Detects potential support from facet normals (does not test occlusion or bridges); recommends brim for small contact. Preserves user temperatures. Wall count, solid layers and adhesion are wired to CuraEngine overrides and preferences. Not a structural or print-quality guarantee. Browser QA: 20x30x40 prism -> Y+90 -> 40x30x20; strength 4 walls / 40% / 40mm/s / 6 solid layers; local slicing passes build-volume checks. Tests include recommendation geometry and presets.

Version 0.5: full catalog of 577 settings from bundled fdmprinter/fdmextruder definitions, 15 categories, 472 editable settings and 105 reference-only settings for the stock single-extruder Ender profile. Spanish upstream descriptions/labels from Cura 4.6 es_ES. Search, dependencies/status, per-setting restore, numeric/enum/list validation, local persistence, JSON export/import. Restricted non-eval expression interpreter resolves all 577 defaults and derived values before sending them to CuraEngine (including speed, flow and infill spacing). Explicit overrides take precedence. Fixed hardware/placement/dual settings are read-only. Basic PLA bounds retained and shown in UI; not equivalent to current desktop Cura/Arachne or plugin functions. Enabled-condition generator expressions for two multi-volume settings are shown as not evaluated. Browser QA: gyroid cube 100 layers, within volume, 2.2s local calculation. All regression tests pass; phone/printer verification remains pending.
Upstream Spanish translation: https://github.com/Ultimaker/Cura/blob/4.6/resources/i18n/es_ES/fdmprinter.def.json.po (same license as Cura).
Generate catalog: python scripts/catalog.py. The generated src/catalog.json is checked in and bundled into app.js for offline access.

Version 0.6: machine registry generated from the bundled definition package (279 reference models, 176 single-extruder Marlin/RepRap candidates; remaining models are reference-only with explicit adaptation reasons). A special non-FFF profile is blocked. Search/brand/model selection, custom rectangular or circular beds, centered or corner XY origin, nozzle/filament size, heated bed, configured thermal limits, geometry/profile JSON export/import. Machine source definitions are loaded locally; active profile is persisted and visited definition assets are service-worker cached. Advanced overrides are namespaced per machine; profile imports check machine identity. Generic G28 start and no-motion end on other machines; catalog-specific leveling/purge must be adapted explicitly in advanced settings. No physical compatibility certification; resin, proprietary postprocessors and multiple-extruder slicing are not implemented.
Build-volume and circular-bed tests now follow selected machine and actual origin, as do recommendation fit, nozzle-dependent layer suggestions and the 2D toolpath preview. Geometry corners outside the circular bed are rejected. Browser QA: Prusa Mk3 profile with 250x210x210 bed and centered circular custom 200x200x300 profile both slice a 20mm cube to 100 layers with zero out-of-volume moves. Existing Ender and regression tests pass.
Generate profiles: node scripts/printers.mjs; python scripts/catalog.py. Machine JSON is served from dist/printers. A first online load is needed for an uncached catalog model; the active loaded machine restores locally.

Version 0.7: 11 editable generic filament starting profiles (PLA, PLA+, PETG, ABS, ASA, TPU95A, PA, PC, PVA/BVOH, HIPS, PP), plus custom spool profiles, JSON export/import, abrasive-fill declaration and spool-diameter checks. Machine-specific declared extruder/hotend/enclosure/hardened-nozzle flags provide contextual warnings. Presets apply temperatures, cooling, retraction, flow, speed and adhesion without changing machine limits. Selection is pending until explicitly applied; pending materials invalidate old G-code. Profiles and advanced overrides are scoped by both machine and material, with legacy PLA migration. Custom spool profiles restore locally on reload.
Generic thermal family ranges reference https://help.prusa3d.com/es/filament-material-guide (checked 2026-11-03); flexible slow-print/no-retraction starting approach references https://help.prusa3d.com/article/flexible-materials_2057 . Speeds, fan and retraction numeric starts are NanoSlice heuristics, not vendor calibration. Supplier datasheets take priority. PVA/HIPS do not enable a second support material: the current workflow remains single-extruder/single-material.
Material-aware recommendations cap speed (TPU default20mm/s) and prefer brim for shrink-prone generic profiles. User customizations remain editable. All resolved heater setpoints are checked against configured machine limits; final G-code is also scanned for M104/M109/M140/M190 over-limit setpoints and blocked if present, including custom start code. No automatic temperature-limit increases or silent temperature reductions on machine changes. Hardware declarations do not certify or upgrade a printer.
Browser QA: ABS preset blocked by stock configured230/70 limits; TPU applied230/50, fan0, retraction0 and20mm/s recommendation, cube sliced to100 layers within volume/temperature bounds; PETG custom230/70 profile created/applied and persisted across reload. Regression tests cover all11 profiles, custom roundtrips, machine/material compatibility, flexible settings, diameter mismatch and raw G-code heater violations. Physical printer/mobile validation remains pending.

Version 0.7.1: standalone /actualizar.html recovery checks an online JSON version response before removing only NanoSlice service workers and caches; saved printer/material preferences remain untouched. Offline or sign-in HTML responses do not clear caches. Content-fingerprinted application and style assets prevent mixing new HTML with old cached code. Version metadata and recovery page bypass the worker cache. Header includes an update link; manifest uses the current product name. Validation: node tests/update.mjs and browser-local recovery -> version 0.7.1 with all 11 material choices. Production deployment metadata checked; authenticated production HTTP inspection was blocked by automatic credential-transmission review. Physical phone and printer checks remain pending.
